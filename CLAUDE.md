# Svenska B1 – AI teacher project

Claude is the **teacher and project lead**. The user (learner) follows. Claude decides the next
lesson, builds it, grades results, and keeps the repo up to date. Don't ask the user for
permission to commit/push — commit and push after every meaningful change.

Repo: https://github.com/bmd007/learning-swedish (branch `main`).

## Resume checklist (read this first after a restart)

0. Read `progress/plan.md` (goal: SFI D national test, old format; backup Swedex A2B1). No time-based
   planning: react to the learner's efforts (grade → next lesson).
1. Read `progress/learner-profile.md` (who the learner is, goals, strengths/weaknesses).
1b. Read `progress/decisions.md` (notes from conversations: preferences, decisions).
2. Read `progress/log.md` (chronological log; the LAST entry says what is in flight and what's next).
3. `ls results/ results/drafts/ feedback/ lessons/` – a results file without a matching feedback file = an
   ungraded attempt → grade it first. `results/drafts/` = unfinished attempts (saved after every
   answer); grade what is there if the learner stopped midway.
4. Check the server: `curl -s localhost:8765/api/lessons`. If down, tell the user to run
   `./start-app.sh` (starts the server and opens the browser), or start `python3 server.py` in background yourself.
5. `git -C . status` – commit/push anything left uncommitted.
6. Continue with the "Next step" from the last log entry.

## The learner

- Native Persian (Farsi) speaker. English fluent. Has SFI C. Finishing Folkuniversitetet B1
  (Rivstart B1/B2, chapters 1–6). Has the book and can send photos of pages.
- Goal: pass **SFI kurs D** (pass/fail, G/IG). Needs B1 in reading + listening (citizenship
  requirement); must also pass speaking + writing (A2 is enough for citizenship, but SFI D needs pass).
- Learning style: dislikes rote memorization; Swedish feels "categorical, not logical".
  → Teach patterns, chunks, contrast with Persian/English, lots of context, stories,
  spaced repetition of errors. Persian explanations when useful. English hints early on, fade later.
- Talk to the user in simple, short sentences. No fluff.

## Architecture

- `start-app.sh [port]` – starts the server (if not running) and opens the app in the browser.
- `server.py` – Python stdlib server (no deps). `python3 server.py [port]`, default 8765.
  - `GET /api/lessons`, `GET /api/lessons/<id>`, `GET /api/feedback/<id>` (latest md)
  - `POST /api/draft` → `results/drafts/<lessonId>__<attemptId>.json` (sent ~0.6 s after every answer, includes raw `state`)
  - `GET /api/draft/<lessonId>` → latest draft; the app resumes from it if newer than localStorage
  - `POST /api/results` → `results/<lessonId>__<stamp>.json` (final; removes the draft)
  - `POST /api/recording?name=..&ext=..` → `recordings/` (gitignored, private)
  - `POST /api/upload?name=..&ext=..` → `uploads/` (photos of handwritten writing, gitignored; served at /uploads/)
- `tools/generate.py` – lesson/test generator using a local Ollama model (default `gemma3:12b`, env
  `OLLAMA_MODEL`). Steps: plan → items per section (JSON schema) → language review (drop/fix) → blind
  self-check of answer keys → code builds ids/tags/shuffles/cover image → validate → audio. Grounded with
  example sentences from Rivstart ch. 1–10 + hand-made lessons. Used by the app panel
  (`POST /api/generate {topic, mode}`, `GET /api/generate/<job>`; jobs in memory, one at a time).
  Generated lessons get `generated: {model, topic, reviewed: false}` → badge "inte granskad av Claude".
  When grading such a lesson, review it and set `reviewed: true` (fix wrong keys first).
- `web/` – plain HTML/JS engine (`app.js`) that renders any lesson JSON. Home = dashboard (days to exam, skill
  meters from `GET /api/progress`, tabs Att göra / Prov / Klara, skill filters). `mode: practice` → learning
  view; `mode: exam` → separate exam view (timer, tabs, question navigator, flags, level verdict). See AUTHORING.
- `lessons/NNN-slug.json` – one file per lesson/test. **Making a new lesson = writing a JSON file.**
- `images/<lessonId>/` – lesson images (served at /images/), referenced by `image: {src, alt, caption?, credit?}`.
- `audio/<lessonId>/<audioId>.m4a` – generated by `tools/build_audio.py` (edge-tts, voices
  sv-SE-SofieNeural (f) / sv-SE-MattiasNeural (m)). Run: `.venv/bin/python tools/build_audio.py [lessons/x.json] [--force]`.
  If no audio file exists, the browser falls back to speechSynthesis. Speakers can be `{voice, pitch, rate}`;
  lines can have `pause`. Real audio: `audio.source: "materials/...m4a"` + `transcript` (see AUTHORING → Audio).
- `tools/fetch_klartext.py` – downloads SR Klartext radio clips (real native speech) to `materials/sr/klartext/`.
- `tools/transcribe.py [--save] <audio>` – local Whisper (openai-whisper "turbo", needs ffmpeg) for real-audio
  transcripts and learner recordings.
- `feedback/<lessonId>__<stamp>.md` – Claude's graded feedback; shown in the app ("Feedback" button).
- `progress/` – learner model (`learner-profile.md`, `log.md`, `errors.md`).
- `materials/` – gitignored private sources. `materials/nok/` = Rivstart B1/B2 extramaterial (exercises,
  audio, transcripts, facit, word lists); see its README. Never commit or publish it. One source among
  others, not the curriculum. B1 ≈ chapters 1–9 (maybe 10); 11–18 are B2.
- `docs/sources.md` – every downloaded source (TTS weights, LibriVox, NST, Klartext …): where from, licence, local path, how to refetch.
- `docs/research.md` – research on SFI D format, citizenship test, agentic tutors, TTS/STT.
- venv: `.venv` (edge-tts). Recreate: `python3 -m venv .venv && .venv/bin/pip install edge-tts`.

### Lesson JSON schema

```
{ id, title, titleEn, minutes, intro, introEn,
  sections: [{ id, title, titleEn, instructions, instructionsEn,
    items?: [...],                      // simple section
    parts?: [{ heading, headingEn, passageTitle, passage, audio, items }] }] }
audio: { id, title, maxPlays (2), speakers: {Name: "f"|"m"}, rate?, script: [{speaker, text}] }
item common: { id (unique in lesson), type, tags: ["area.sub"], q, qEn, explain, explainEn }
  mcq:   options[], answer (index)
  select: dropdown; options[] on the item OR on the part (shared, shown as a list) → matching tasks
  short: free answer 1–5 words; answers[] = accepted key phrases (contained match); teacher re-checks wrong ones
  gap:   q contains "___", base (dictionary form hint), answers[] (accepted)
  order: words[] (shuffled), answers[] (accepted sentences, punctuation ignored)
  write: minWords, maxWords, bullets[]          → graded by Claude
  speak: maxSeconds, bullets[], audio? (examiner question played first) → recording + browser transcript, graded by Claude
```
Tags drive the learner model (e.g. `ordföljd.inversion`, `ordföljd.bisats`, `adjektiv.bestämd`,
`verb.preteritum`, `preposition`, `läs.slutsats`, `hör.detalj`, `skriv.mejl.formell`, `tal.argumentera`).

## Lesson design rules

- Short: 10–15 min per lesson, **one topic per lesson**. The learner's study time is unpredictable.
- **Media in every lesson:** related images (`images/<lessonId>/`, hand-drawn SVG or free photos,
  see docs/AUTHORING.md "Images") and audio where it fits. Text-only lessons are boring.
- Exam task shapes first: SFI D (old national test) and Swedex A2B1 (see progress/plan.md). Mix in grammar
  only where errors show it is needed.
- Record in `progress/decisions.md` decisions, preferences, facts about the learner, and parts of a
  conversation with real value (hard-won findings, research worth keeping). Skip casual questions
  whose answers are easy to find again.

## Teaching loop

1. User takes a lesson in the browser → results JSON saved.
2. Claude grades: auto items are scored already; Claude grades `write` and `speak` items
   using the SFI D criteria (see docs/research.md: content, adaptation to reader, coherence,
   textbindning, ordförråd, grammatik, stavning; speaking adds interaction + uttal).
   Note: the speak transcript comes from Chrome's speech recognition – it can mishear; judge
   fluency/grammar, not small transcription errors.
3. Write `feedback/<same name as results>.md`: score, strengths, top 3 problems with simple
   rules/patterns (+ Persian contrast when useful), corrected version of the text.
4. Update `progress/errors.md` (tag → count, examples), `progress/learner-profile.md`, append to `progress/log.md`.
5. Build the next lesson targeting the weakest tags (aim ~60–70% success rate), plus
   SFI-D-shaped practice. Generate audio. Commit + push. Tell the user it's ready.
